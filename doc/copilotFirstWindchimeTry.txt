## 🎵 How to map widget inputs to windchime sounds

Use the existing channel semantics from WidgetChannel.cpp:

- `position` → pitch, tube index, or strike location
- `velocity` → strike energy / loudness / damping
- `isActive` → trigger a new chime event
- `previousPosition` / `previousVelocity` → optional motion smoothing

A practical mapping for windchimes would be:

- **One widget channel = one chime tube**
- `velocity` controls **how hard the chime is struck**
- `position` controls **which resonant frequency is used**
- `isActive` triggers a note onset
- Optional motion or acceleration can add **randomized shimmer / damping**

That gives you a very natural “windchime-like” behavior without needing physical actuators.
